# Contributing to copairs

Thank you for your interest in contributing to `copairs`! Bug reports, documentation improvements, tests, fixes, and new features are welcome.

## Before you start

Check the existing issues and pull requests to avoid duplicating work. For substantial changes, please open an issue first so the approach can be discussed with the maintainers.

## Development setup

Fork and clone the repository, then create the development environment with [uv](https://docs.astral.sh/uv/):

```bash
git clone git@github.com:YOUR_USERNAME/copairs.git
cd copairs
uv sync --all-extras --dev
```

## Making changes

Create a focused branch and follow the conventions already used in the codebase. Add or update tests for behavioral changes and use NumPy-style docstrings for public APIs.

Before opening a pull request, run the tests:

```bash
uv run python -m pytest -s
```

Run the Nix-pinned Ruff linting/formatting and Nix formatting checks without changing your files:

```bash
nix build --no-link --print-build-logs .#checks.x86_64-linux.formatting .#checks.x86_64-linux.pre-commit-config
```

These are the same checks used by CI; replace `x86_64-linux` with your Nix system on other platforms. They also verify that the portable hook configuration matches the Ruff version pinned by `flake.lock`, without building the full development environment. To apply automatic fixes and formatting, run `nix fmt`.

Without Nix, run the equivalent Ruff hooks with [Prek](https://prek.j178.dev/); installing a Git hook is not required:

```bash
uv tool install prek
prek run --all-files
```

This command applies Ruff's automatic fixes and formatting. To run it automatically at commit time, optionally run `prek install`. The configuration also works with `pre-commit run --all-files` and `pre-commit install` for contributors who already use pre-commit.

The committed hook configuration is generated by Nix and pins the same Ruff version used by CI. Entering `nix develop` installs the hook automatically for Nix users. Prefer these pinned commands over an independently installed Ruff, which may have a different version.

After intentionally updating the Nix tooling, regenerate and commit the portable configuration:

```bash
nix run .#update-pre-commit-config
```

## Submitting a pull request

Use clear, descriptive commits and keep each pull request focused on one change. In the pull request description:

- explain what changed and why;
- link any related issues;
- describe the tests you ran; and
- note any compatibility or performance implications.

All CI checks must pass before a pull request can be merged. If you have questions, open an issue and the maintainers will be happy to help.
